## Rollback without data loss

Disable mail first to stop new claims, then receiving before rolling API release back. Stop the configured worker gracefully through its existing supervisor; allow the current iteration to finish, with the supervisor's established timeout, and retain180-second leases for recovery. Do not invent a15-second drain guarantee: the current worker waits for an active iteration before closing its pool, and supervisor timeout must be verified operationally.

Do not drop migration0038, reset poster tables, delete objects, rewrite historical uploads or restore used rights. Keep the newer public/read routes while a Pris consumer still needs them; roll consumers back compatibly using previous artifacts, never copy the old static roster into the new branch. Rolling a source manifest back is an intentional source version change: reconcile preserves history and cannot reopen used rights. Unknown provider outcomes need manual inspection, not automatic resend. Recover abandoned attempts only through guarded worker logic. Re-enable only after affected A01–A22 checks and readiness pass again.
